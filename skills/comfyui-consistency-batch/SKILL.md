# 一致性与批量手册

> DSH 执行层（跑 API、提交工作流、取图）：见 `comfyui-studio` 技能。


## 一 · 先分清三种"一致"

用户说「要一样的」，可能是三种完全不同的事：

| 类型 | 含义 | 难度 |
|---|---|---|
| **构图一致** | 同姿势、同构图 | 🟢 固定 seed + 固定提示词即可 |
| **风格一致** | 色调/质感/画风统一 | 🟢 固定前缀 + 固定参数 |
| **身份一致** | 还是同一个人/同一款产品 | 🔴 SD1.5 原生几乎做不到 |

**先问清是哪一种，否则会给出过重的方案。**

## 二 · 固定前缀法（最省事，也最被低估）

```
[固定前缀 · 一字不改]
photorealistic product photography, soft studio lighting, neutral background

[变量 · 只改这段]
a red apple / a blue mug / a leather wallet
```

配合固定 seed + 固定采样参数，**风格与产品一致性基本够用**。

## 三 · seed 的真实作用

| 做什么 | 结果 |
|---|---|
| 同 seed + 同提示词 + 同参数 | 几乎完全相同的图 |
| 同 seed + 改提示词 | **不是"同一个人换场景"**，而是"相似构图下的新图" |

🔴 **seed 是随机数起点，不是人脸特征锁。** 别把它当身份锁定用。

## 四 · 身份一致的现实手段

| 手段 | 可靠性 | 代价 |
|---|---|---|
| 参考图注入（IPAdapter 类） | 较高 | 需装节点+模型，吃显存 |
| 固定 seed + 极详细外貌描述 | 低-中 | 换机位就变人 |
| 专用 LoRA（自训） | 高 | 需训练，**超出这套技能职责** |
| 局部重绘 | 中 | 工作流变长 |

**必须明说**：SD1.5 纯靠提示词做不到稳定同一张脸。

## 五 · 产品比人物容易

产品图（同一款包/设备）比人脸容易，因为形状特征能描述清楚。
做法：把产品特征固定成 6-7 个关键词前缀，只换背景与机位。

## 六 · 队列式批量生产

**推荐队列，不推荐大 batch**：

| 方式 | 优点 | 风险 |
|---|---|---|
| `batch_size=N` | 一次提交 | N 大→OOM，全批一起失败 |
| 队列多次提交 | 稳、可控、部分失败不连累 | 慢一点 |

队列做法：
1. 固定提示词与参数，只递增 seed
2. `SaveImage.filename_prefix` 带序号
3. 记录每次的结果与耗时（失败可重跑单张）
4. 中途检查：先跑 3 张看质量，再放量

## 七 · 批量时的成本预估

用实测公式先算：
```
单张耗时 ≈ 0.62s/步 + 0.4s（512×512）
批量总时长 ≈ 单张 × N + 排队开销
```
例：20 步 → 12.3s/张 → 50 张约 **10 分钟**（不含失败重试）。

## 八 · 交付格式

```
要哪种一致（构图/风格/身份）
手段（按可靠性排，说明代价）
固定什么、变什么
预期（能到什么程度，到不了的说清）
批量方案（队列参数、命名、失败处理）
```

## 九 · 红线

- 不承诺「纯提示词做到同一张脸」
- 不把 seed 说成身份锁
- 需要装节点/模型时明说（含显存）
- 自训 LoRA 超出职责，明确交回
- 批量前先跑 3 张验证，不直接放量
