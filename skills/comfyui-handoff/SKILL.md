# ComfyUI 资产交接（comfyui-handoff）

> **DSH 适配**：本技能来自 WorkBuddy 专家团版。「成员/派单/回执」= 你的分步执行与交付记录，「本团」= 你。单 agent 场景下纪律不变。

把真实生成结果整理成可交付资产包，并**诚实标注缺口**。

## 1. 资产导出

- 从生成工程师交付的真实结果（文件名 + `/view` 或 `get_result_image` 字节）落盘到用户指定目录。
- 图像：PNG/JPG；视频：MP4/WebM（依 Save 节点类型）。保留原始分辨率，不二次压缩失真。
- 命名规范：`{workflow}-{seed}-{timestamp}.{ext}`，便于复现与回溯。

## 2. 交付文档

- **交付清单**：每个资产的真实路径、生成所用 workflow 版本、checkpoint/LoRA、关键参数（步数/CFG/分辨率/seed）。
- **复现指引**：如何能拿到相同结果（环境 + 工作流 + 模型 + 参数）。

## 3. 诚实缺口清单（铁律）

- 环境不通没生成的 → 标「未生成·环境阻塞」。
- 生成失败/OOM 的 → 标「失败·原因 + 建议重跑参数」。
- 用户要但本机缺模型的 → 标「缺模型·需用户自备」。
- **绝不把"设想中会有"列进交付物**——交付物只能是真实落盘文件。

## 4. 红线

- 交付未真实落盘的文件 → 每条交付物必须对应真实生成的字节。
- 把"计划生成/设想效果"写进交付清单 → 只列真实存在的资产。
- 隐瞒失败/OOM → 缺口必须如实标注，不粉饰。

## 5. 输出物

- 资产目录（真实文件）、交付文档（清单 + 复现指引）、诚实缺口清单。

## 6. 判定标准（怎么算交付过关）

- ✅ 每条交付物对应真实文件：路径存在 + 字节 > 0 + SHA-256（命令按平台选，见 comfyui-sop §11）。**「见某目录」但目录为空 → 直接不过**。
- ✅ 关键数字自己重测，不转述上游：字节 / SHA / 尺寸 / `status_str` 逐项对上。
- ✅ 命名 `{workflow}-{seed}-{timestamp}.{ext}`，时间戳取自 `execution_start`（非文件 mtime）。
- ✅ 无版本号就用 sha256 锁版本，**不许瞎编「v1.0」**。
- ✅ 缺口三类齐全：缺模型·需用户自备 / 本次未做 / 不在本团判定范围。
- ❌ 不过：单次采样当固定值（显存写「约 3.8 GiB」而非实测区间）。
- ❌ 不过：未做确定性复跑却写「逐字节可复现」。

## 7. 做不到什么（边界）

- **不能**交付未真实落盘的东西：设想效果、计划批次，一个字不进清单。
- **不保证**产物可用性 / 审美 / 商用合规（归用户与法务，口径见 comfyui-sop §9）。
- **不能替代**用户拍板（选哪张、要不要放大 / 批量）。
- **不替用户补模型**：缺模型只标注「需自备」。
- **不承诺**确定性复现：未同环境重跑比 sha256 前，只说「同参数可再跑」（口径见 comfyui-sop §9）。
