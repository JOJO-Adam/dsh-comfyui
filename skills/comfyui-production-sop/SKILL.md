# ComfyUI 生产 SOP

> **DSH 适配**：本技能来自 WorkBuddy 专家团版。「成员/派单/回执」= 你的分步执行与交付记录，「本团」= 你。

本工作室的**唯一判断依据**。

## 1 · 六层故障模型（诊断必须落到一层）

| 层 | 现象 | 首要判据 |
|---|---|---|
| 模型层 | 全黑/全灰/完全无形 | 换模型重试 |
| **VAE 层** | 花图、色彩错乱（**最高频**） | 换回自带 VAE |
| 文本编码层 | 提示词不生效 | 检查 CLIP 连线与权重语法 |
| 采样参数层 | 过饱和/欠饱和/噪点/彩边 | 对照参数表 |
| 构图层 | 主体重复/过大/畸形 | 分辨率与提示词冲突 |
| 资源层 | OOM/极慢 | 分辨率、batch、分块 |

**一句话**：说不清哪一层，就等于没诊断。

## 2 · 实测优先于传言

**禁止**「一般建议 steps 20-30」这类没有适用条件的话。
给参数必须同时给：**模型 + 分辨率 + 采样器**。

我们的实测基线（SD1.5 · 512 · M5 16GB 统一内存 · MPS；采样时刻 2026-11-03 14:28–15:02 +08:00，`/prompt`→`/history` 轮询 wall-clock、粒度 0.2s，每配置 3 轮取中位、`--cache-none`）：

| 项 | 实测值（中位，min–max） |
|---|---|
| steps 20 / cfg 7 / euler | **21.4s（20.7–21.7）** |
| 步数成本 | **≈0.82s/步 + 7.8s 固定**（最小二乘粗估，非严格线性） |
| cfg 2.0 | 细节糊、偏暗（21.9s，21.5–22.7） |
| cfg 16.0 | 过饱和、背景被抹平（23.8s，23.0–24.1） |
| steps 4 | 青色彩边、形体崩（11.1s，10.9–11.3） |
| size 768 | **主体重复（3 个苹果）、耗时 69.5s（67.4–74.8，3.3×）** |
| 采样器 heun | 38.9s（38.2–44.2，比 euler 慢 1.8×） |

## 2.5 · 🔴 两种限制必须分开（2026-10-18 重要纠正）

**这是最容易犯的错：把「我这台机器的表现」当成「模型的极限」。**

| 类型 | 具体例子 | 换高性能硬件能解决吗 |
|---|---|---|
| **模型限制** | SD1.5 直接生成 768 出主体重复（训练分辨率 512）· cyberpunk 语义偏置 · 手部畸形 · 毛孔级细节 · 复杂分区光照 | ❌ **不能**。换更强的卡跑 SD1.5 768 一样出三个苹果 `[推断·跨硬件]` |
| **硬件限制** | 生成慢 · 显存不足 · 跑不动 SDXL/Flux · batch 大就 OOM · 直接 1024×1536 要等很久 | ✅ **能**。纯配置问题 |

### 关键认知

- **崩坏（主体重复/畸形）是模型问题**，与你机器多快无关
- **慢是硬件问题**，不能拿"慢"当作"不可行"的理由
- 我们的实测基线是 **Apple M5 16GB（中低配）· MPS**；买家的机器千差万别，**先审计后给方案**（`comfyui-hardware-audit`），不做「大家多数用什么」的假设

### 因此必须做到

1. **报时间必标硬件**：我们的「512×768 40.0s（39.6–41.1）」只对 M5 成立；换机型一律重新实测，不猜倍数
2. **先问配置再给方案**：答案随机器而变——高配可直接上 SDXL 原生 1024×1024、不必 hires fix 绕路；但这台机器到底能不能上，以它的探针实测为准（`comfyui-hardware-audit`），不按显存分档
3. **不要把 SD1.5 的结论套给 SDXL/Flux**：SDXL 原生 1024，Flux 原生更高，它们的"安全分辨率"完全不同

> 📌 一句话判据：**「这是模型不会，还是我的机器不够快？」**
> 答"模型不会" → 换模型，不是加硬件
> 答"机器不够快" → 加硬件或降配置，不是换模型

## 3 · SD1.5 安全操作区间
```
分辨率   512（原生）· 要更大 → hires fix，不要直接生成
步数     12 起步 · 20 标准 · 30 精细
CFG      5–9（甜点）· 调 CFG 零时间成本，可放心试
采样器   euler / dpmpp_2m+karras（结构要求准）
         heun（要极质量，接受 1.8× 耗时）
         ancestral（画面活泼，但易出局部伪影）
```

## 4 · 分辨率是最大的坑

**768 直接生成会出主体重复**，因为 SD1.5 训练分辨率是 512，超出分布后模型会把画面切成多个区域各自生成。

**正确做法**：512 生成 → LatentUpscale ×1.5-2.0 → 二次 KSampler（**denoise 0.45-0.6**）→ 解码

## 5 · 五块交付（第 0 块必填）

0. **角色分工**（谁改的图、谁定的参数、谁查的故障，具体到判断）
