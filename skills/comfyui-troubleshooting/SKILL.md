# 崩图排查树（带实拍复现）

> DSH 执行层（跑 API、提交工作流、取图）：见 `comfyui-studio` 技能。


## 一 · 症状 → 层（先分诊，别先调参）

```
出图异常
├─ 全黑 / 全灰 / 纯色块
│   ├─ 模型没加载完整（文件损坏/下载中断）→ 换模型重试
│   ├─ VAE 不匹配 → 换回模型自带 VAE
│   └─ 潜空间全零 / CLIP 没接上 → 检查 conditioning 连线
│   ⚠️ **实测证伪**：提示词为空**不会**出黑图——SD1.5 空提示词会出随机内容
│      （我们跑过：空正向+空负向 → 出一张随机的人物照片）。别把空提示词当黑图原因。
│
├─ 花图 / 色彩错乱 / 细节糊成彩色噪点
│   └─ 🔴 VAE 版本错（最高频）→ 换 VAE 重跑，参数不用动
│
├─ 全屏彩色噪点、无任何结构
│   ├─ steps ≤ 2 → 提到 12 以上重跑
│   └─ 采样器与调度器不匹配 → 回 euler + normal
│
├─ 主体清晰但过饱和 / 塑料感 / 强光斑
│   └─ CFG 过高 → 回 5-9 区间
│
├─ 灰蒙蒙、细节少、不听提示词
│   └─ CFG 过低（< 3）→ 提到 5-9
│
├─ 主体周围有青/彩色光环、边缘彩边
│   └─ steps 过低（4 左右最典型）→ 提到 12 以上
│
├─ 主体重复（一张图里出现多个相同物体）
│   └─ 🔴 生成分辨率超出**模型**训练分布 → 回到原生分辨率，用 hires fix 放大
│       ⚠️ **与硬件无关**：SD1.5 在 4090 上跑 768 一样出三个苹果。
│          4090 只是更快，不会让它变对。换 SDXL（原生 1024）才解决。
│
├─ 主体过大 / 被裁切 / 构图失控
│   └─ 分辨率过低（256-384）→ 提到 512
│
├─ 主体消失 / 画面杂乱没重点
│   └─ 🔴 提示词稀释：并列主体过多或修饰词堆太多
│       → 验证：把提示词砍到只剩主体重跑，回来了就是稀释
│       → 修复：主体前置、只留一个主体、删掉 8k/masterpiece 这类占位词
│
├─ 横幅/竖幅构图怪异、主体偏小或位置偏移
│   └─ 🔴 非主流宽高比：超出模型训练分布（SD1.5 以 1:1 为主）
│       → **实测澄清**：768×256 **不会把主体「拉伸变形」**，而是主体变小、偏在中间、
│         两侧内容空泛——直觉上容易误说成"变形"，实际是构图分布问题
│       → 验证：改回 1:1 重跑，主体回到正常占比就是比例问题
│       → 修复：用接近 1:1 或 4:3 / 3:4 生成；要横幅竖幅走 outpainting 或后期裁剪
│
├─ 肢体畸形 / 五官崩
│   ├─ 分辨率过低（像素不够画细节）
│   ├─ 提示词里同时出现矛盾要素
│   └─ 模型本身能力不足（SD1.5 画手确实差）
│
└─ OOM / 卡死 / 异常慢
    ├─ 分辨率过高（768 比 512 慢 4.2 倍）
    ├─ batch_size 过大 → 改队列多次提交
    └─ 未启用分块/低显存模式
```

## 二 · 五个实拍复现（可直接对照）

下列现象来自我们的真跑记录（SD1.5 · 512 · M5 MPS · 固定种子 42）：

| 现象 | 复现条件 | 我们看到了什么 |
|---|---|---|
| **彩边 + 形体崩 + 环绕光晕** | steps=4 | 苹果变成圆球状，周围一圈怪异青绿色光晕 |
| **过饱和 + 强光斑 + 背景变灰** | cfg=16 | 苹果高光爆亮，木纹被「抹平」成灰底，细部出现噪点 |
| **主体重复** | size=768 | **一张图里出现 3 个苹果**，分布在画面对角 |
| **细节糊 + 偏暗 + 构图散** | cfg=2 | 木纹纹理丢失，苹果边缘不锐，整体发闷 |
| **双蒂伪影** | euler_ancestral | 苹果顶部出现两个果柄状突起 |

🔑 **这五张图就是排查树的"标准样本"**：用户说"我的图怪怪的"，发来一对比就能落到某一层。

## 二之二 · 12 类故障全量验证（2026-10-18 实跑）

造了 12 类故障逐条核对排查树判断：

| 编号 | 故障造法 | 实际结果 | 判定 |
|---|---|---|---|
| F01 | 空正向 + 空负向 | **出了随机人物照，不是黑图** | ❌ 原判断错误，已修正 |
| F02 | 想造花图（VAE 错配） | 只有一个 VAE，**造不出来** | ⚠️ 无法复现 |
| F03 | steps=1 | 模糊色块 | ✅ |
| F04 | steps=4 | 青色彩边 + 光晕 | ✅ |
| F05 | cfg=18 | 过饱和 + 强光斑 + 背景灰 | ✅ |
| F06 | cfg=1.0 | 偏暗、细节丢失 | ✅ |
| F07 | 768×768 | **三个苹果（主体重复）** | ✅ |
| F08 | 256×256 | 严重裁切 | ✅ |
| F09 | 「白天 AND 午夜」冲突 | 主体与场景全变 | ✅ |
| F10 | 21 个并列主体 | **苹果消失，只剩风景** | ✅（补充为新条目） |
| F11 | 768×256 | **主体偏小、构图偏移，不是拉伸** | ❌ 原描述错误，已修正 |
| F12 | 256×768 | 同上 | ❌ 同上 |

**结果：9/12 准确，2 处文档错误被实测纠正，1 类因环境限制无法复现。**

### ⚠️ 必须承认的两个局限

1. **花图造不出来** —— 本机只有一个模型及其自带 VAE，无法制造「VAE 与模型不配套」。
   所以「换 VAE」这条建议**原理正确但未在本机验证**，引用时要说清。
2. **空提示词不出黑图** —— 反直觉结论已写进树里，避免以后按"常识"误导用户。

## 三 · 唯一可靠的定位方法

**一次只改一个变量，重跑对比。**

推荐顺序（从便宜到贵、从高概率到低概率）：

```
1. 换回模型自带 VAE       ← 最高频，先排除
2. steps 提到 20
3. cfg 回 7.0
4. 分辨率回 512
5. 提示词简化到只剩主体
6. 最后才怀疑模型文件本身
```

每改一步跑一次，**看现象是否消失**。消失了就是那一层的问题。

## 四 · 三个高频误判

### ① 把 VAE 问题当参数问题
花图/色彩错乱时用户常以为 CFG 太高。**换 VAE 立刻正常**，调参白费几十分钟。

### ② 把分辨率问题当模型能力问题
256 出人像必然畸形——不是模型差，是像素不够画五官。

### ③ 把参数问题当提示词问题
cfg 16 崩图时，加多少负面词都没用。**判据**：负面词加了没改善 → 去查参数，别继续堆词。

## 五 · 交付格式

```
## 分诊
现象 → 最可能哪一层（给判据）

## 验证动作
一个动作 + 看什么

## 修复
具体改什么

## 若仍不对
下一层查什么
```

## 六 · 红线

- 未排除 VAE 前不许归因给参数
- 不许让用户一次改多个变量
- 不许说「多试几次」「换个种子试试」（这是逃避诊断）
- 用户只给文字描述时，明说「描述可能不准，建议发图」
